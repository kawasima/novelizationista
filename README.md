# novelizationista

A visual novel engine that shows talking characters over backgrounds and slides. It is written in React; a work uses it by rendering a single `NovelApp`. The scenario, character sprites, backgrounds, BGM and voices all live in the work's own project, and the engine contains nothing specific to any one work.

It also ships two scripts: one turns a plain-text manuscript into scenario JSON, the other synthesizes the voice lines with VOICEVOX.

## Creating a work

### Project setup

Create a Vite + React + TypeScript project and add the engine as a local path dependency. The engine has no build step; its `src/index.ts` is consumed as is.

```json
{
  "dependencies": {
    "novelizationista": "file:../novelizationista",
    "react": "^19.2.0",
    "react-dom": "^19.2.0"
  }
}
```

A `file:` dependency can end up loading React twice, so tell Vite to use the work's copy. With `base: './'` asset paths keep working when the site is served from a subdirectory.

```ts
// vite.config.ts
export default defineConfig({
  plugins: [react()],
  base: './',
  resolve: { dedupe: ['react', 'react-dom'] },
})
```

### Configuration and entry point

Describe the work as a `NovelConfig` and pass it to `NovelApp`. All paths are root-relative to `public/`; at runtime they are resolved against Vite's `BASE_URL`.

```ts
// src/novel.config.ts
import type { NovelConfig } from "novelizationista";

const config: NovelConfig = {
  scenario: "/scenarios/episode1.json",
  credits: "/scenarios/credits.json",   // omit for no ending credits
  opening: {
    title: "Title of the work",          // omit to show no text on the title screen
    background: "/images/backgrounds/opening.webp",
    bgm: "/bgm/theme.mp3",
  },
};

export default config;
```

```tsx
// src/main.tsx
import { createRoot } from "react-dom/client";
import { NovelApp } from "novelizationista";
import config from "./novel.config";

createRoot(document.getElementById("root")!).render(<NovelApp config={config} />);
```

`<title>` and the OGP tags belong in the work's `index.html`. The engine does not touch them.

### Where assets go

Nothing is enforced, but the rest of this README assumes this layout.

```
public/
  scenarios/episode1.json     scenario (generated by txt2scenario.py)
  scenarios/credits.json      ending credits
  images/characters/          sprite sheets and their meta JSON
  images/backgrounds/         backgrounds (16:9)
  images/slides/              slide images
  bgm/                        BGM
  audio/                      voice lines (generated by generate.py)
scenario/
  episode1.txt                manuscript
  config.json                 conversion settings for the manuscript
voices.json                   voice settings per character
```

## Character sprites

A character is one sprite sheet plus a meta JSON that gives the position and role of each frame. There are three roles: `idle`, `blink` and `talk`. While a character speaks, the engine cycles through its `talk` frames, so registering the closed-mouth frame as a `talk` frame too makes the mouth alternate between open and closed.

```json
{
  "frameWidth": 543,
  "frameHeight": 724,
  "frames": [
    { "index": 0, "name": "neutral",      "role": "idle",  "x": 0,    "y": 0, "width": 543, "height": 724 },
    { "index": 1, "name": "talk",         "role": "talk",  "x": 543,  "y": 0, "width": 543, "height": 724 },
    { "index": 2, "name": "eyes_closed",  "role": "blink", "x": 1086, "y": 0, "width": 543, "height": 724 },
    { "index": 3, "name": "neutral_talk", "role": "talk",  "x": 0,    "y": 0, "width": 543, "height": 724 }
  ]
}
```

`offsetX` on a frame shifts where it is drawn, left or right. If a sprite fails to load, only that character goes missing; the dialogue can still be advanced, and the cause is logged to the console.

## From manuscript to scenario

Scenario JSON can be written by hand, but it is easier to write a plain-text manuscript and convert it with `tools/txt2scenario.py`.

```sh
python3 node_modules/novelizationista/tools/txt2scenario.py scenario/episode1.txt \
  --config scenario/config.json -o public/scenarios/episode1.json
```

### Manuscript format

```
@background /images/backgrounds/rooftop.webp
@bgm /bgm/lunch_break.mp3
## 屋上

昼休みの屋上には、ほかに誰もいなかった。

@slide /images/slides/letter.png
蓮「これ、下駄箱に入ってた。差出人の名前がない」

葵「へえ。**放課後、屋上で待ってます**、ね。行くの？」

@slide none
蓮「[文化祭]の準備があるから、断るつもりだけど」

葵「……ふーん。断るんだ」
```

| Syntax | Meaning |
|---|---|
| `## Scene name` | Starts a scene. The name appears in the scene menu |
| `@background path` | Background of the next scene. Without it, the previous background carries over |
| `@bgm path` / `@bgm none` | BGM of the next scene. `none` stops it. Without it, the current track keeps playing |
| `@transition` | Makes the next scene a narration over a dark screen |
| `@slide path` / `@slide none` | Shows a slide from the next line on. It stays until `none` or the end of the scene |
| `名前「セリフ」` | A spoken line, when the name matches `characters[].name` in `config.json` |
| Any other line | Narration (no sprite, no voice) |

Lines longer than `maxLineLength` (default 100) are split into several lines at sentence ends (。？！) that are outside brackets.

### Inline markup

Words in dialogue or narration can carry a link, a help text or emphasis. The markup characters are removed from the displayed text and do not affect the voice.

| Syntax | Meaning |
|---|---|
| `[word]` | Applies the glossary (`terms`) entry for that word |
| `[shown text\|key]` | When the shown text differs from the glossary key |
| `[word](https://…)` | A one-off link |
| `**word**` | Emphasis |
| `` `word` `` | Code style |
| `\[` `\*` `` \` `` | The literal character |

### Conversion settings

```json
{
  "title": "Title of the work",
  "characters": [
    { "id": "aoi", "name": "葵",
      "spriteImage": "/images/characters/aoi.webp",
      "spriteMeta": "/images/characters/aoi_meta.json" },
    { "id": "ren", "name": "蓮",
      "spriteImage": "/images/characters/ren.webp",
      "spriteMeta": "/images/characters/ren_meta.json" }
  ],
  "readings": {
    "下駄箱": "げたばこ"
  },
  "terms": {
    "文化祭": {
      "help": "Held on the second weekend of October. Every class runs a stall",
      "auto": "first"
    },
    "生徒会": {
      "href": "https://example.com/student-council",
      "help": "Ren is its treasurer"
    }
  },
  "maxLineLength": 100
}
```

`readings` are substitutions used only for speech synthesis; the displayed text stays as written.

A `terms` entry takes any of `href` (link target), `help` (shown on hover) and `style` (`em` or `code`). With `"auto": "first"`, the word is marked at its first occurrence in each scene even without markup. To match spellings other than the key, add `"match": ["spelling 1", "spelling 2"]`.

On screen, marked words use the accent color, with a dotted underline when they have help and a solid one when they are links. Help appears above the dialogue window when the mouse is over the word. On touch devices the first tap shows the help and the second tap advances to the next line. Links open in a new tab and do not advance the dialogue. While the text is still being revealed, marked words are styled but inert, and a click shows the full line as usual.

## Generating voice lines

`voice-gen/generate.py` synthesizes every spoken line in the scenario JSON with VOICEVOX, writes the mp3 files to `public/audio/`, and writes each path back into the line's `audio` field. Narration lines get no voice.

It needs `voicevox_core` importable from Python, a VOICEVOX Core installation (ONNX Runtime, dictionary, voice models) and `ffmpeg`. Point `VOICEVOX_ROOT` at the VOICEVOX Core installation.

```sh
VOICEVOX_ROOT=~/voicevox/voicevox_core \
python3 node_modules/novelizationista/voice-gen/generate.py \
  --scenario public/scenarios/episode1.json --voices voices.json --public-dir public
```

Voices are assigned per character ID in `voices.json`. `vvm` is the voice model file name and `style_id` is the speaker style. If any character that appears in the scenario has no voice, the script stops before synthesizing anything.

```json
{
  "aoi": { "name": "葵", "vvm": "0.vvm", "style_id": 6,  "speed": 1.2, "intonation": 1.1 },
  "ren": { "name": "蓮", "vvm": "4.vvm", "style_id": 11, "speed": 1.2, "intonation": 1.0 }
}
```

File names are a hash of the character ID, the text to be read and the voice settings. Existing files are not regenerated, so after editing one line only that line is synthesized again. Changing a character's voice or speed in `voices.json` regenerates all of that character's lines. Old mp3 files that are no longer referenced are not deleted; remove them by hand if they bother you.

Running `txt2scenario.py` rewrites the scenario JSON and drops the `audio` fields, so run `generate.py` after it. When no dialogue changed, nothing is synthesized and the paths are simply reattached. Putting both in the work's `package.json` keeps this easy.

```json
"scripts": {
  "scenario": "python3 node_modules/novelizationista/tools/txt2scenario.py scenario/episode1.txt --config scenario/config.json -o public/scenarios/episode1.json",
  "voice": "python3 node_modules/novelizationista/voice-gen/generate.py --scenario public/scenarios/episode1.json --voices voices.json --public-dir public"
}
```

## Ending credits

The `lines` of `credits.json` scroll from top to bottom. An empty string is a blank line. A line that needs a link is written as an object. With `bgm`, the music switches to that track for the credits.

```json
{
  "bgm": "/bgm/ending.mp3",
  "lines": [
    "Title of the work",
    "",
    "Cast",
    { "text": "葵 — VOICEVOX:四国めたん", "href": "https://voicevox.hiroshiba.jp/" },
    { "text": "蓮 — VOICEVOX:玄野武宏", "href": "https://voicevox.hiroshiba.jp/" }
  ]
}
```

## Controls and settings

Click or press the right arrow key to advance, and the left arrow key to go back one line. Advancing while the text is still being revealed shows the full line first; the next advance moves on. Advancing while the voice is playing stops it and moves to the next line. The menu at the top right jumps to any scene.

The settings panel at the top right has the following items. Values are saved in the browser.

| Item | Effect |
|---|---|
| BGM / Voice | Volume |
| 速度 (speed) | Speed of the voice, text reveal and mouth animation (0.8–2.0×). Pitch is preserved, and BGM is not affected |
| 文字 (text) | Size of the dialogue text and window (0.8–1.5×) |
| リンク (links) | When off, links in the dialogue do not open on click. Guards against accidental clicks during a screening |

## Adjusting the look

Layout dimensions are CSS custom properties. Override them by setting the same variables on `.app` in the work's CSS. The defaults are chosen so the text is readable from the back of a venue with a projector screen.

| Variable | Default | Meaning |
|---|---|---|
| `--nv-text-size` | `calc(min(3.8vh, 5.2vw) * var(--nv-text-scale))` | Dialogue text size |
| `--nv-speaker-size` | `calc(min(3vh, 4.4vw) * var(--nv-text-scale))` | Speaker name size |
| `--nv-window-width` | `min(94vw, 150vh)` | Width of the dialogue window |
| `--nv-window-height` | `calc(27vh * var(--nv-text-scale))` | Minimum height of the window; 36vh on portrait screens |
| `--nv-window-max-height` | `60vh` | How far the window grows when the text does not fit |
| `--nv-window-bottom` | `3vh` | Space below the window |
| `--nv-character-height` | `72vh` | Height of the character sprite |
| `--nv-character-bottom` | `12vh` | Bottom edge of the sprite, set so it tucks behind the window |
| `--nv-accent` | `#ffd36b` | Color of the name plate and marked words |

`--nv-text-scale` is set from the 文字 slider in the settings panel; do not override it.

## Development

```sh
npm install
npm run typecheck
```

The engine has no screen of its own. Check changes by running `npm run dev` in a work's project; because it is a `file:` dependency, edits to the engine show up in the work's dev server right away.
